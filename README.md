# 飞牛音乐酷狗增强 · fnmusic_kugou_pro

> 为飞牛 OS 的【音乐】接入**自建 KuGouMusicApi** 作为外部音源：搜索、在线播放、
> 歌词、封面、扫码登录、**边播边存**。
>
> 采用 **零侵入 Unix Socket 接管**架构 —— 不修改飞牛官方 nginx、二进制或数据库。
>
> **本仓库是独立分叉分支**，与上游 `fnmusic_ext_kugou` **不共存运行**。

## ⚠️ 安装前必读

### 第一步：先卸载旧版！

**顺序绝对不能反。**

```
① 【应用中心】卸载 fnmusic_ext_kugou —— 是"卸载"，不是"停用"
② 安装本应用 fnmusic_kugou_pro
```

**为什么必须先卸？**

两个版本的卸载脚本都会"把 socket 还原回去"。
如果你在**新版运行中**去卸载旧版，旧版会**把新版正在用的 socket 删掉** ——
新版进程还活着，但已经没人能连上它，表现就是**"新版突然坏了"**。

本应用已内置防护：安装时记录告警；**启动时若发现音乐接口被别的扩展占着，
会直接拒绝启动并说明原因**（此时不触碰任何 socket，飞牛音乐不受影响）。

若已装乱，见 [FAQ Q1](FAQ.md#q1-能和上游-fnmusic_ext_kugou-同时装吗)。

### 第二步：填你实际部署的 KuGouMusicApi 地址

```
正确格式：http://<主机>:<端口>       ← 以你自己的实际部署为准
```

上游文档默认值写的是 `8899`，但那是上游作者的假设。
在很多机器上 **`8899` 已被其它服务占用**，填错的表现是
**"接口连得上、但搜不到歌"**。

Docker 部署的话，`docker ps` 看端口映射 `0.0.0.0:XXXXX->3000/tcp`，取 `XXXXX`。

> 填错了也不用重装 —— 到设置页改一下，**保存立即生效**。

## 这是什么

上游 [`fnmusic_ext_kugou`](https://github.com/ai2ku/fnos-music-ext-kugou-fpk) 通过接管飞牛音乐的本地
Unix socket，把酷狗音源接进了【音乐】App，思路非常巧妙。

本项目**基于它（GPL-2.0）深度重构**，解决了一批实际使用中遇到的硬问题 ——
其中包括**若干配置与权限处理上的安全问题**。

**不是重写，是有明确目标的深度修复。** 上游署名与协议完整保留。

### 本分叉的核心改进

#### 🔴 修了 3 个真实安全漏洞

| 漏洞 | 说明 |
|---|---|
| **配置加载与写入缺少输入校验** | 上游在读取配置文件与写入配置项时均**缺少输入校验**。本分支已全面加固：配置文件改为**逐行解析并校验键名与取值**；所有写入路径统一经 `_sanitize_env_value()` 归一化。 |
| **`kugou_url` 无校验 → SSRF** | 该地址无校验地成为 HTTP `base_url`，可指向任意内网地址且探测结果部分回显。现加 `_sanitize_kugou_url()`，仅放行 `http(s)://`。 |
| **凭据文件权限 0666** | 存着 `TOKEN/USERID/DFID/T1/MID/GUID/DEV/MAC`，**同机任意用户可读写**，且扫码写回时沿用旧权限。现改 **0600** + 统一原子写入入口 `write_env_updates()`。 |

#### 🟢 边播边存，从"从未生效"到"真的能用"

- **超过 48 MiB 的无损曲目不再静默丢失**
  上游归档字节只有内存缓存一个来源，而内存缓存对 > 48 MiB 的内容
  **直接丢弃且不记日志** ⇒ 高音质 FLAC 的边播边存**从来没生效过**。
  现改为**字节直传落盘**。
  **实测：最大 61.05 MiB（64,012,767 字节）的 FLAC 成功归档。**

- **飞牛 App 上终于会被触发**
  上游判定要求"无 `Range` 头"或"恰好 `bytes=0-`"，而 App 播放器是
  **分块随机读取**（`Range: bytes=262144-524287` + 多 worker 预取），
  两种形态都不发 ⇒ **一次都不触发**。
  现改为**累积覆盖判定**（合并多次 Range，覆盖到 total 才算读完，
  total 取自上游 `Content-Range`）。

- **不再存下你没听完的歌**
  上游用**无界队列**，上游比客户端快时整首会被提前拉完，
  于是**切歌跳过的歌也被归档**。现绑定"客户端把流读干净"，
  客户端断开时 `cancel()` 下载任务（顺带省带宽）。

- **省内存**：上游归档后**不释放**内存缓存（实测 8×48 MiB 占约 472 MiB，
  超出配置的 320 MiB 上限）。现归档后 `pop` 缓存。

#### 🟢 升级不再丢东西

| 数据 | 位置 |
|---|---|
| 配置 / 登录令牌 | `/vol1/@appconf/fnmusic_kugou_pro` |
| 运行缓存 | `/vol1/@appdata/fnmusic_kugou_pro` |
| 在线收藏 | `/vol1/@apphome/fnmusic_kugou_pro` |
| **归档去重索引** | **`<落盘目录>/.fnmusic_save_index/`** |

上游每次安装重建 `.env`（**丢登录、丢设置**）；去重索引写在**安装目录**里，
而飞牛**覆盖安装会替换整个安装目录** ⇒ 升级后索引归零、已存曲目被当成
没存过、重下一遍，落成 `歌名 (2).flac`。

**现已全部迁移**。注意最后一行：**去重索引跟着曲库走，不跟着应用走** ——
无论怎么覆盖安装、甚至卸载重装，都不会重复下载。

#### 🟢 一整套遗留 Bug 修复

- **7 条路由实际不可达** —— `{subpath=path}` 是 `{subpath:path}` 的笔误，
  框架会把它编译成**含花括号的字面量路径**，永不匹配、静默 404。
  涉及 `search/artist`、`search/album`、`artist/detail`、`artist/list`、
  `album/list`、`album/detail`、`track/album-detail/list`。
- **归档网络超时设置不生效** —— 代码写死 60s，配置项形同虚设。
- **`.env` 出现空值键就启动崩溃** —— 脚本会写出 `KEY=`，而
  `os.environ.get(K, 默认值)` 在"键存在、值为空"时返回**空串**（默认值只在
  键不存在时生效），`float("")` 抛异常，**模块导入即失败**。现已容错回落。
- **配置"写得进、读不回"** —— 表现为"保存成功、重启恢复默认"。已补 21 键回读白名单。
- **安装向导填的地址被默认值覆盖** —— 上游无条件写默认值，丢弃用户输入。
- **应用图标空白** —— 只带两张图，且 `icon_64.png` 里装的其实是 256×256。
  已重制并补齐 **16/24/32/48/64/72/96/128/256** 全套尺寸阶梯 + 字面量兜底
  `icon_{0}.png`（官方应用同做法）。
  > ⚠️ **装过本应用早期未发布构建的，需重启一次 NAS** —— fnOS 按 appname
  > 维护系统级图标缓存，换包不会自动刷新。详见 [FAQ Q30](FAQ.md#q30-装好后应用图标是灰的--空白)。
- **`.pyc` 与运行时不匹配** —— 包里是 3.11 编译，运行时是 3.12，
  字节码被**直接忽略**，纯死重量。现按目标运行时重编。
- **重复配置键**、**测试残留**、**测试硬编码 `/tmp`**、**测试污染真机**等清理。

#### 🟢 新增"音乐接口占用检测"

启动时检测 `/var/run/trim_music.socket` 是否已被**其它音源扩展**接管；
是则**拒绝启动并说明占用者**（此时不碰任何 socket）。

#### 🟢 应用全面独立改名

应用名、socket 名、`/tmp` 临时文件、网关前缀、路由前缀、桌面启动项
**一处不留旧名**。

## ⚠️ 已知限制（请务必知情）

本项目的原则是**如实声明边界，不粉饰**。

### 1. 权限模型仍是 root

- ⚠️ `config/privilege` = **`run-as: root`** —— 接管 socket 需要这个权限。
- ⚠️ **设置接口没有自带鉴权**，依赖上游 nginx 兜底。
  （上述配置与权限问题**已加固**，但权限模型未变。）
- ⚠️ 桌面入口 **`allUsers: true`**，socket 权限 **0666**。

> **⇒ 请勿在多人共用且互不信任的 NAS 上裸装本应用。**

### 2. 无看门狗

代理进程若被 `kill -9` 或 OOM，**socket 文件还在但没有监听者**，
而还原逻辑只在 stop / uninstall 路径触发 ⇒ **飞牛音乐整体不可用**，
需到应用中心重启本扩展恢复。

### 3. 官方 App 的「转码」开关会导致在线歌曲播放失败

飞牛【音乐】开启转码时会发 `POST /music/api/v1/track/transcode`，
而本扩展策略是"GET 全接管、非 GET 全透传"，该请求被原样转发给音乐本体，
本体不认在线曲目、回 401，播放中断。

**规避方法：在官方 App 设置里关掉「转码」。**

> **诚实说明**：本应用**未在代码层修复此问题**，
> 仅在转发路径增加了**取证日志**（`forward_to_upstream_diag()`），
> 用于记录请求体形态、鉴权字段、上游 401 的 `error_code`。
> 这属于**"已知问题 + 规避方法"，不是"已修复"**。

### 4. 版权曲目可能无法保存

部分曲目即使已登录也可能**没有下载权限**（能播、存不下来）。
这是上游版权策略，**不是本应用缺陷**，无法绕过。

### 5. 依赖未锁定

`requirements.txt` 只有版本下限，**无 hash 校验**。请自行评估供应链风险。

### 6. 无自动迁移

从**上游**迁移不支持自动保留登录态：卸载上游 → 安装本应用 → **重新扫码登录**。

## 安装

### 前置：部署 KuGouMusicApi

本项目**不自带音源服务**，需要你自行部署
[KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)（社区有 Docker 镜像）。

```bash
# 示例：Docker 部署（端口按需改）
docker run -d --name kugou-api -p 4000:3000 <kugou-api-image>
```

部署完记下**实际端口**，下一步要用。

### 安装本扩展

```
① 【应用中心】卸载旧版 fnmusic_ext_kugou（若有）
② 应用中心 → 手动安装 → 选择 fnmusic_kugou_pro-*.fpk
③ 按安装向导填写：
     音源地址        http://<主机>:<端口>     ← 你的实际地址
     音质            按需选择
     搜索超时        默认即可
     曲库目录        你的共享音乐库路径
④ 启动应用
⑤ 打开设置页 → 扫码登录（可选，登录后可访问个人歌单）
```

**向导只有 4 个字段**，其余配置（边播边存开关、落盘目录、单曲最大字节、
归档超时、是否写标签/歌词/封面等）都在**设置页**里，**保存即生效**。

### 仍存在（如实声明）

- 仍以 **root** 运行
- 设置接口**无自带鉴权**（依赖 nginx 兜底）
- 桌面入口 **allUsers**

### 数据流向

本应用是**纯本地代理**，请求只在
「飞牛音乐 App ↔ 本扩展 ↔ 你自建的 KuGouMusicApi」之间流转，
**不向本应用作者或任何第三方服务器发送数据**。

> 请自行确认你的 KuGouMusicApi 部署可信 —— 那才是数据出口。

### 凭据处理

- `.env` 权限 **0600**，原子写入
- 扫码登录写回走统一入口（临时文件 + `os.replace` + `chmod 600`）
- **日志不落凭据**：诊断日志只记**长度**不记值，`cookie`/`token` 一律不写文件

> ⚠️ 贴 Issue 时请仍**自查一遍日志**，确认没有 token / userid。

## 从源码构建

```bash
git clone <仓库地址> && cd fnmusic_kugou_pro
bash tools/build.sh          # 产出 out/fnmusic_kugou_pro-<版本>.fpk
```

`tools/build.sh` 会依次完成：清杂 → 重编 `.pyc` → 打 `app.tgz`
→ 回填 `manifest.checksum`（飞牛用 **MD5**）→ 打外层 `.fpk`
→ 跑自检，**自检不过不产出 `.fpk`**。

> 上游仓库里也有一份 `build-fpk.sh`，可作参考；本项目的脚本
> 在其思路上补齐了 `.pyc` 重编与发布前自检。

**打包顺序不能变**：先清杂 → 打 `app.tgz` → 回填 `manifest.checksum`
（飞牛用 **MD5**）→ 打外层 `.fpk`。

> ⚠️ **绝不能把 `.env` 打进包**：飞牛覆盖安装是**先解包、后跑 callback**，
> 包里若是带了一份 `.env`（哪怕空模板），它会在 callback 有机会迁移之前
> **把用户真配置盖掉** —— 正好复现本分叉修掉的"升级丢登录"。

**开发提示**：

- 跑测试必须 `env -u PYTHONPATH` —— 宿主注入的 `PYTHONPATH` 会盖过
  venv 的包，制造 `ModuleNotFoundError` 之类**假故障**。
- 改了 `.py` 一定要**重编 `.pyc`**（源 size / mtime 要对上），
  否则 Python 加载旧字节码，让你误判"补丁没生效"。
